# TeleAvatar 2 底盘运动指令

通过 ROS 2 控制机器人底盘移动的操作手册。依据官方文档
<https://www.dexteleop.com/docs/teleavatar-2>（2.4 接入 ROS 2 Topic、4.5 底盘控制、6.5 底盘控制示例）
以及 2026-11-14 在本机的实测整理。

## 1. 环境

| 项目 | 值 |
|---|---|
| 主机 | Ubuntu 22.04 + ROS 2 Humble（默认 Fast DDS） |
| 机器人 IP | `192.168.31.244` |
| 通讯端口 | `9000/tcp`（zenoh 路由器） |
| ROS 域 | `ROS_DOMAIN_ID=29` |
| bridge | `zenoh-bridge-ros2dds` v1.9.0，位于 `bin/` |

注意：

- bridge 必须用 v1.9.0。v1.10.x 要求 glibc 2.38，Ubuntu 22.04 只有 2.35，无法运行。
- 脚本必须用系统 Python（`/usr/bin/python3`，3.10）。默认的 `python3` 是 miniconda 的 3.13，无法导入 rclpy。直接用 `./chassis_move.py` 运行即可。
- 当前主机通过 WiFi 连接机器人（延迟约 35 ms）。官方文档要求有线连接，长期使用建议接网线。

## 2. 机器人端前提

在机器人"系统配置"（底部导航"开发"→"配置"）中：

1. 运行模式设为 **API**。
2. 打开**底盘**开关。
3. 点"保存配置"，再点"生效"，然后物理重启机器人。

底盘不依赖 `/api/fsm/enable` 心跳，不需要额外使能。

## 3. 启动步骤

所有文件在 `/home/jhz/workspace/teleavatar2/`。

**终端 A**：启动 bridge，保持运行，关闭即断开。

```bash

```

**终端 B**：检查通讯。


## 4. 运动指令

### 4.1 接口

| 项目 | 值 |
|---|---|
| 话题 | `/api/chassis/velocity` |
| 消息类型 | `std_msgs/msg/Float32MultiArray` |
| 数据 | `data=[vx, vy, wz]`，必须是 3 个有限数值 |
| 单位 | `vx`、`vy`：m/s；`wz`：rad/s |

### 4.2 方向对应关系

底盘是三轮全向（Kiwi）结构：后轮在立柱后方，两个前轮分列左右。

| 动作 | 指令 | 确认情况 |
|---|---|---|
| 后退 | `vy` 负 | 轮子指令已验证为前后方向；正负号由现场观察确认 |
| 前进 | `vy` 正 | 由"后退"反推，未单独实测 |
| 右移 | `vx` 正 | 轮子指令已验证为横向；**左右正负号为推定，未经现场确认** |
| 左移 | `vx` 负 | 同上 |
| 原地旋转 | `wz` | 已实测可转；**正值对应顺时针还是逆时针未确认** |

轴向的判断依据是实测的轮子指令（`/chassis/joint_cmd`，顺序为 1、2 号前轮和 3 号后轮）：

- `vx=-0.05` → `[0.25, 0.25, -0.5]` rad/s：后轮全速、两前轮半速，是横移。
- `vy=-0.05` → `[-0.433, 0.433, 0]` rad/s：后轮不转、两前轮等速反向，是前后直行。

### 4.3 常用命令

```bash
./chassis_move.py --vy -0.05 --duration 3    # 后退约 15 cm
./chassis_move.py --vy  0.05 --duration 3    # 前进约 15 cm
./chassis_move.py --vx  0.05 --duration 5    # 右移约 25 cm
./chassis_move.py --vx -0.05 --duration 3    # 左移约 15 cm
./chassis_move.py --wz  0.2  --duration 2    # 原地旋转约 23°
./chassis_move.py --wz -0.2  --duration 2    # 反向旋转约 23°
```

位移 ≈ 速度 × 时长，转角 ≈ 角速度 × 时长。可以同时给多个分量，例如 `--vy 0.05 --wz 0.1`。

### 4.4 脚本参数

| 参数 | 含义 | 默认值 |
|---|---|---|
| `--vx` | 横向速度，m/s | 0 |
| `--vy` | 前后速度，m/s | 0 |
| `--wz` | 角速度，rad/s | 0 |
| `--duration` | 运动时长，s | 2 |
| `--max-lin` | 线速度上限，m/s | 0.2 |
| `--max-ang` | 角速度上限，rad/s | 0.5 |

脚本以 10 Hz 持续发布指令，结束或按 Ctrl+C 时连续发 1 秒全零停车。

### 4.5 不用脚本，直接用 ros2 命令

```bash
source env.sh
ros2 topic pub -r 10 /api/chassis/velocity std_msgs/msg/Float32MultiArray "{data: [0.0, -0.05, 0.0]}"
# Ctrl+C 后发一次全零：
ros2 topic pub --once /api/chassis/velocity std_msgs/msg/Float32MultiArray "{data: [0.0, 0.0, 0.0]}"
```

## 5. 安全与行为特性

- **机器人 API 不做速度限幅**。上限只由 `chassis_move.py` 的 `--max-lin` / `--max-ang` 把关，放宽前先确认场地。
- **停发保护**：停止发布超过 1 秒，机器人自动把目标清零并减速停车。
- **全零指令**：立即把目标置零，再按减速度限制停车，不是瞬时刹停。
- **加减速**：线加速度不超过 0.3 m/s²，线减速度不超过 0.6 m/s²；角向数值相同，单位 rad/s²。
- **数据格式错误的后果**：数组长度不是 3 可能导致底盘控制节点退出；NaN 或 Inf 可能使速度状态失效。
- **开环控制**：没有里程计反馈，实际位移和转角与理论值会有偏差，往返不能精确回到原位。
- 运动前确认周围无人员和障碍物；异常时立即停发指令，物理急停按用户手册执行。

## 6. 状态与排查

```bash
source env.sh
ros2 topic echo --once /chassis/joint_states   # 三个轮子的位置 rad、速度 rad/s、力矩 N·m
ros2 topic echo /chassis_target_vel            # 机器人收到的目标速度
ros2 topic echo /chassis/joint_cmd             # 下发给三个轮电机的速度指令
```

`/chassis/joint_states` 是轮子关节状态，不是车体速度或里程计。

| 现象 | 检查 |
|---|---|
| 脚本提示"没有订阅者" | bridge 是否在运行；是否 `source env.sh`；机器人是否启用底盘 |
| `ros2 topic list` 话题很少 | `ROS_DOMAIN_ID` 是否为 29；`nc -z -w 3 192.168.31.244 9000` 是否通 |
| 指令发了但"没动" | 速度 0.05 m/s 很慢，位移小不易察觉；用第 6 节的话题确认轮子是否在转；确认方向没有搞错（见 4.2） |
| `ImportError: rclpy` | 用了 conda 的 python，改用 `./chassis_move.py` 或 `/usr/bin/python3` |
