2026-11-14 跑通"抓取沙包 → 带着沙包右移 → 放到桌面"所用的脚本。所有脚本都在 B70 服务器（连接信息见

运行前确认：本机的 zenoh bridge（`../start_bridge.sh`）没有在跑；容器里没有别的 `main.py`；现场无人在手臂和底盘路径上。

## 递交任务

```bash
./run_handover.sh --check    # 可选
./run_handover.sh            # 倒数 2 秒启动，约 30-45 秒完成
```

1. 到递交起始姿态，夹爪张开。手臂下垂（刚重启）时先后退 30 cm 抬臂再回位，需要身后有空间。
2. 夹爪张开 5 秒（日志逐秒倒数），这时把沙包放进右夹爪；然后夹紧。
3. 启动自检：模型给的第一个目标离当前姿态超过 1 rad，或模型认为夹爪该张开，就不启动，夹爪保持夹紧。
4. 模型推理递出，模型输出"张开"时松手并保持张开；松手后 3 秒手臂收回起始姿态。上限 600 步。

- 模型：B70 容器 `ta2-handover-5907`（checkpoint `sandbag_handover_224_v1` 第 5907 步，第二张显卡，`127.0.0.1:8001`），
  提示词 `Hand the sandbag to the person.`。部署和重启方法见 `/home/jhz/workspace/B70_Handover_模型部署指南.md`。
- 起始姿态取自训练数据 B70 `/root/ta2_lerobot/put_224_v1` 全部 161 个回合第一帧的均值。
- 2026-11-15 两次实测都成功：模型先等约 5 秒再伸手，伸出幅度比示范小，接收者需要迎上来接。
- 可调参数放在 `--` 后：`--open-s`（张开等待秒数）、`--max-steps`、`--after-release-s`、`--back-cm`。

## 组合任务（搬运 + 递交）

```bash
./run_combo.sh --check    # 可选：只做检查（同时检查 8000 和 8001 两个推理服务）
./run_combo.sh            # 倒数 2 秒启动，约 2 分 10 秒完成
```

起始条件与 `run_task.sh` 相同；另外接收的人要站在第二张桌子旁。

1. 后退 30 cm → 抬臂 → 回位 → 左移 144 cm → 按沙包图像位置微调 → 抓取模型抓起沙包。
2. 右移 72 cm → 停 15 秒 → 右移 72 cm。
3. 把沙包放到桌面，夹爪松开，等 5 秒。
4. 夹爪闭合重新夹起。夹爪开度小于 0.15（没夹到沙包）就中止，不进入递交。
5. 夹着沙包回到递交起始姿态，直接开始递交模型推理；模型输出"张开"时松手，3 秒后手臂收回。

- 两个模型在任务开始时都连接并预热好，中途切换不停顿。
- 抓取模型可切换：默认用旧模型（5221 步，端口 8000）；`GRASP_PORT=8002 ./run_gesture_combo.sh`（或 `run_combo.sh`）改用新模型
  （`sandbag_rec_224_v2` 9264 步，容器 `ta2-sandbag-9264`，与旧抓取模型共用第一张显卡）。
  新模型从静止的起始姿态不会自己伸手（2026-11-15 两次实测都停在原地），所以用 8002 时脚本自动加 `--grasp-prime 1`：
  先把右臂沿示范的平均伸手方向带出约 0.46 弧度（1.3 秒），再交给模型；这样实测 1 次，1.3 秒后闭合并抓住沙包。
  原地单测抓取：`GRASP_PORT=8002 ./run_combo.sh -- --grasp-only --no-align`；只收臂张爪：`./run_combo.sh -- --home-only`。
- 抓取前会按沙包在头部图像里的位置微调底盘（最多 10 cm）；回程第二段右移扣掉这段横向微调，前后微调在抓取后立即退回，
  所以机器人停在出发位置。`--no-return-comp` 关掉这个补偿。`full_task.py`（`run_task.sh`）没有这个补偿。
- 可调参数放在 `--` 后：`--wait-s`（松开后等待秒数）、`--dwell-s`、`--right-cm`、`--left-cm`、`--place-blend`（放置高度）、
  `--handover-max-steps`、`--after-release-s`、`--no-align`。
- 2026-11-15 连跑 4 次，流程都完整走完（123-132 秒）。其中 2 次沙包递到手上，2 次落在桌面上：
  递交回合开始后约 4 秒模型就松手，不一定等手伸过来。接收的人要在手臂回到递交起始姿态时就把手伸到夹爪前方。
- 重新夹起的判据 0.15 是估计值（夹住沙包时读数 0.35-0.45，空夹时的读数没有实测过）。

## 网络不稳时的保险（2026-11-16，`run_task_net.sh` / `stop_task_net.sh`）

两种启动方式并存，流程和参数完全相同，只差启动外壳：

| 方式 | 启动 | 停止 |
|---|---|---|
| 原版（不带丢包检查和重试） | `./run_gesture_combo.sh`、`./run_combo.sh`、`./run_handover.sh` | `./stop_task.sh` |
| 网络保险版 | `./run_gesture_combo_net.sh`、`./run_combo_net.sh`、`./run_handover_net.sh` | `./stop_task_net.sh` |

`run_*_net.sh` 只是设置 `RUN_TASK=run_task_net.sh` 后调用对应的原版启动脚本。两个停止脚本可以互换使用（停的是同一个任务）。

本机到 B70 走 Wi-Fi，丢包严重时曾两次在启动阶段 SSH 超时。网络保险版里：

- **启动前测丢包**：ping B70 十个包，丢包率超过 20% 就不启动（`NET_MAX_LOSS=100 ./run_..._net.sh` 可跳过，`NET_MAX_LOSS=10` 可更严）。
- **机器人不动的三步自动重试**：启动前检查、传手势模板、回传日志图像，连不上时隔 3 秒再试，最多 3 次（`NET_TRIES`）。
  回传改为先确认压缩包完整再删 B70 上的临时目录；三次都失败时数据留在容器的 `/tmp/ta2_task_<时间>` 里。
- **运行任务那一步不重试**：连接断在途中时任务可能还在机器人上跑，重发就是第二个控制程序。这时脚本会提示并自动尝试发停止信号。
- **停止信号重试**：`stop_task.sh` 和 Ctrl+C 都最多发 5 次，5 次都没送达会明确提示去按急停。

注意：任务运行途中断线时，容器里的任务很可能继续跑（按 docker exec 的一般行为判断，没有实测），本机这时停不下它。
另外不要在有任务运行时修改 `run_task.sh` / `run_task_net.sh`：bash 是边读边执行的，运行中的那一次会在收尾阶段出错。

## 底盘开环换算

- `vx` 正 = 右移，`vy` 正 = 前进。
- 实际位移 ≈ 0.6 × 速度 × 时长（横向卷尺实测：名义 50 cm 实际 30 cm；前后方向沿用同一比例，未实测）。
- 时长 = 目标距离 ÷ (0.6 × 速度) + 补偿（0.05 m/s 用 0.06 s，0.10 m/s 用 0.08 s）。
- 例：右移 72 cm → `0.1 0 0 12.08`；右移 144 cm → `0.1 0 0 24.08`；后退 30 cm → `0 -0.1 0 5.08`。

## 已知问题

- 抓取只在沙包位于桌面中间略偏右、瓶子那一排前方时成功，策略不跟踪沙包位置。
- `goto_first_frame.py` 从重启后的下垂姿态抬臂只在离桌子较远处验证过一次；紧贴桌子时可能磕到桌沿。
- 后退再回位后，机器人到抓取位置时曾比原来近约 5 cm，原因未确定，抓取前建议拍图核对。
- `place_back.py` 里的抓取点姿态是 2026-11-14 那一轮的，沙包位置变化大时需要改 `REACH_R`。
- `full_task.py` 的抓取回合在"夹爪闭合后右臂实测关节角回到持物姿态 0.15 rad 以内并保持 0.3 s"时结束（2026-11-15 实测闭合后 9.5 s 触发；模型自己把手臂收回就要约 9 s）。
- `full_task.py` 不检查现场有没有人，运行前自己确认。
